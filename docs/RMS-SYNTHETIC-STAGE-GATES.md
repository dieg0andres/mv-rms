# MAU-168 — synthetic stage gates

This slice implements MAU-25 revision 3 under the November 22, 2026 fixture-only build direction. It starts on master `25e8f4edcede91470881e2802c2927831b609606` and pins independently reviewed MAU-167 `56f5573912be5c3d69c428033728c6b2d659e345`. It does not turn an RMS record into a decision, a grant, research credit, or a runnable release. It never calls Paperclip, a connector, a job, or an evidence store. No Stage 2B or release authority is implied.

## Operator and API contract

From an authenticated exact Test Plan detail, an authorized fixture principal follows **Synthetic stage gates for this exact version**. The browser form is CSRF-protected. Writers enter an invented authority reference, revision and digest for freeze/release, or an invented impact reason for invalidation. The page uses the same transactional service as the JSON API. The history label is the *last recorded state*, not current authorization. A Test Plan remains a draft; this deliberately does not certify its substantive completeness, feasibility or scientific merit.

`GET /api/v1/test-plans/{plan_id}/versions/{version_id}/synthetic-gates` returns ordered receipts and impact edges. `POST` requires `Idempotency-Key` and `{"operation":"freeze","expected_sequence":0,"authority":{"reference":"fixture:example","revision":1,"digest":"<canonical decision SHA-256>"}}`; `release` uses expected sequence 1 with its own receipt. `invalidate` uses expected sequence 1 or 2 and a nonblank `reason` instead of `authority`. No other transitions are permitted. Invalidation links to the exact preceding event and terminates that version's stream; it is a restrictive local fixture record, not a revocation of external authority. A correction or lost grant denies new release and does not silently append an event or alter prior history. Scope is rechecked before receipt retrieval, including retries. A valid replay returns the historical receipt only, not permission to advance; changed payload reuse and stale sequence are `409`. Invalid proof/transition is `400`, no assigned plan scope is indistinguishable from missing (`404`), and no global role is `401`/`403`. Replies are private and not cached.

## Fixture boundary

Only explicit local Django test settings enable the slice. `RMS_SYNTHETIC_STAGE_GATES` is a mapping keyed by the stable Test Plan ID, with `readers` and `operators` lists of authenticated principal IDs (strings). An operator must also be a synthetic editor; the founder viewer role never writes here. An empty/missing fixture exposes no gate. Normal views cannot configure any of these settings. `tests/django_stage_gate_tests.py` builds a complete invented example through the unchanged MAU-167 intake and plan paths.

Per-plan fixture settings supply `blockers: []` (including when no blocker applies), `artifacts` with invented `code_sha256` and `data_sha256`, and `authority` and `rights` maps, each with one current record per operation. Each record binds its fixture-only reference, positive revision, policy `fixture:MAU-168:v1`, operation, status, complete scope and aware `[effective_at, expires_at)` interval. Rights must also match the actor and purpose `synthetic_gate_only`. The service computes the canonical digest and compares the command with the current decision; the command itself cannot supply policy, scope, status, blockers, or rights. Scope includes exact plan, hypothesis, investigation and MAU-167 intake versions plus the existing plan row/configuration/link digests, the intake row digest and invented artifact digests. Release rechecks both the current release record and every retained freeze binding, and runs MAU-167's current prior-research, family and Source rights checks under the shared lineage lock. Related variants and legacy/unbound drafts cannot freeze. Invented digests name synthetic artifacts only; this slice verifies no external bytes. It allocates no attempt or evidence event, updates no ledger, and changes no search/export scope.

## Schema, recovery and verification

`0010_synthetic_gate_events` is an atomic additive migration after MAU-167 `0009`. No update/backfill of prior records. The new table has protected foreign keys and PostgreSQL guards on predecessor scope/order and UPDATE, DELETE, and TRUNCATE. App rollback: remove the fixture config and retain the schema and immutable history; this is intentionally not a reversible drop migration. On a migration failure, stop and verify the unchanged history and migration state; don't stamp or reset. On later integration, reconcile migration leaves with the release branch, review table/sequence rights for the ordinary runtime (only the needed SELECT/INSERT and sequence access; never owner, UPDATE, DELETE or TRUNCATE), then re-test populated migration, guard enforcement, exact restored events and permissions. No installed migration or principal changes are part of MAU-168.
