# Follow a research case through RMS

Use this walkthrough in a workspace authorized for invented records. The example follows a fictional case called **Bluebird**, using invented source text and observations. Editors enter records. Founder viewers can follow the same chain by opening saved versions. The build identifier in the workspace details identifies the software serving the page.

## Create the research record

1. Open **Sources** and choose **Create Source**. Give the source a stable ID, supply the requested citation and rights information, and attach a small text file containing your invented observation. Choose **Save immutable version**. Open history and note the source ID and version.
2. Open **Ideas** and create Bluebird. Describe the mechanism and select the exact source version under **Exact Source-version contributions**. Explain what the observation contributes. When two sources contribute different evidence, record each contribution against its own version.
3. In **Research context**, create or select a research family. Choose **Create research case with manual assessment**. Record what prior work you checked, the related records, and the limitations of that search. Set the case owner, next action, and any blocker. A related variant can stay in its existing family.
4. Create a hypothesis from the saved idea and select the exact case and family association. Describe a measurable claim, a competing explanation, and an observation that would falsify the claim. Save the hypothesis and inspect the source and case versions it cites.
5. Open that hypothesis version and create a **Strategy Specification and Test Plan**. Define the baseline, any individually named variations, the data requirements and the criteria you will use to interpret a result. Record which criteria are mandatory. You can save an incomplete draft and return to its missing fields. For an externally performed data check, record the exact requirement, configuration, observed outcome and limitations.

## Record an attempt and interpret its outcome

This section applies when the saved Test Plan offers **Runs and Results for this exact version**. A registration records externally reported activity. The example uses invented values throughout.

1. Open the link from the exact plan version. Choose the configuration and copy its resolved parameter digest. Register an attempt with its own synthetic external reference and the code, dependency, dataset and environment identities requested by the form. Open the saved attempt.
2. Under **Record an update**, record a failed event with an invented reason, such as an incomplete input file. Use the retry action to register a second attempt against the same configuration with a new synthetic reference. Follow the links between the attempts. Both retain their own execution history.
3. Record the retry moving to running and then completed. Publish a result against that completed event. Enter a sample assessment and observation for each applicable predefined criterion, explain the readings and include invented artifact text. Open the result to inspect the rule, outcome, artifact digest and exact plan version together.
4. For a transcription error, return to the attempt and choose **Correct the current result**. Enter a reason, the corrected assessment and its supporting invented artifact. Open both entries under **Immutable result versions**. The first keeps its original outcome and evidence. The successor identifies the version it corrects.

For example, with a mandatory rule requiring an invented reading above zero, a sufficient sample with a reading of −1 fails that criterion. A documented transcription correction to +2 can satisfy the same rule. The run remains completed in both versions. A criterion pass and an independent decision are recorded separately.

## Hand off an exact version

- Share the link from the exact saved version and state the next action. The collection's latest link can move after a correction. From a case, use its owner, recorded blocker and next action to identify who should act.
- Use **Search records** on builds that expose it to find a source, idea, family, case, hypothesis or Test Plan. Select **Include earlier versions** when looking for an original that has since been corrected. Open runs from their exact Test Plan and results from their attempt.
- When two editors revise the same record and one receives a conflict, open the current history, review what was saved and decide whether a new correction is still warranted. Preserve the competing editor's record.
- Record founder decisions in Paperclip under the applicable project procedure. An invented attempt, retry or sample result earns zero real research-cycle or qualification credit.
